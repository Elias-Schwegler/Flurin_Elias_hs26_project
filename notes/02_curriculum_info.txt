DSPRO1 – HS26 – Course Information Background & Goals DSPRO1 is the ﬁrst of two data science project modules. DSPRO1 incorporates three competences: - managing a group project using the CRISP-DM framework - conducting an end-to-end data science project - discussing ﬁndings in the broader context of sustainability Students taking DSPRO1 have not yet received a formal introduction to many relevant areas, such as machine learning, data engineering or machine learning operations. The theoretical foundations for these topics will be developed later in their studies. We therefore follow the Marxist heuristic that Das Sein bestimmt das Bewusstsein or, more simply put, learning by doing. Consequently, the focus of DSPRO1 is not on complex algorithms or advanced data engineering. Instead, the module guides students through the entire data science pipeline step by step and puts emphasize on clear and reproducible decision making, implementation and reporting. The ﬁnal product will be a visual representation (e.g. a dashboard) to either present the results from explorative data analysis, statistical modelling or classical machine learning. Working with foundation models or GenAI is not desired. Students will work in groups of, favourably, two. The association of students to groups will be approached in Week 1. Students are free to create their own groups. There will be no random shuNling. Each group is associated to one coach that supervises the project throughout the semester. 
Sustainability and Energy One of the ﬁrst key challenges for each group will be to select a project topic. DSPRO1 is associated with the HSLU Impact Program, which fosters sustainability in education and research. Consequently, all groups will be expected to align their projects with one or more Sustainable Development Goals (SDGs). Within the broader context of sustainability, a more speciﬁc thematic focus will be deﬁned for each semester. In HS26, all groups will work on topics related to energy. Early in the semester, students will receive an introduction to sustainability, as well as an overview of crucial challenges in the energy sector from an industry expert.

Project Management & Reporting The above curriculum contains mentioning of CRISP-DM, which is a prominent framework for structuring data science projects. An overview can be found here: https://www.datascience-pm.com/crisp-dm-2/ In addition, we will use GitHub, a platform for version control and collaborative software development. Each group will create a repository, which will serve as the central workspace for all project-related code, documentation, and deliverables throughout the semester. 
Initialize GitHub To simplify the combination of CRISP-DM and GitHub, we provide a template repository: https://github.com/curdon/dspro01_hs26_template Once all group members have registered for GitHub, one member of the group should open the template repository and create a new group repository by selecting “Use this template” → “Create a new repository” (upper right). Please use the following naming convention for the group repository: `dspro01_hs26_group<XX>`. The group number (XX) will be communicated to you separately. The repository contains a README.md ﬁle that will be completed throughout DSPRO1 and will ultimately serve as the ﬁnal project report. The chapter structure is provided and corresponds with the steps, as described in CRISP-DM. The README also contains important deadlines for deliverables as well as links to additional information and resources. The repo contains a folder structure to store code. This can be seen as a non-binding suggestion and individually expanded or changed by each group. All group members and all coaches must be added to the group repository as collaborators: Settings → Collaborators → Add GitHub username

GitHub Collaboration The commit history should clearly show that all group members have actively contributed to the project. Unbalanced commit histories will impact individual gradings. A recommended workﬂow is as follows: 1. Each group member clones the repository on their local computer. 2. Whenever you start working on a new deliverable, create a new branch from main (assuming that Main always reﬂects the current state of development). 3. Work on this branch, as a team or by creating additional sub-branches per user. 4. Once the deliverable is due and all work on the task has been completed, create a Pull Request. You should add your coaches as reviewers. 5. Pull Requests will be merged into Main during coaching session. A short demonstration of this workﬂow will be provided during the lecture. 
Grading Schema Final grades consist of two weighted components: 30% of the ﬁnal grade is based on the deliverables completed during the semester: - Throughout the semester, there will be six submissions corresponding to project milestones. - The submission deadlines can be found in the project template repository or in this overview document. - Each of the six submissions contributes 5% to the ﬁnal grade. 70% of the ﬁnal grade is based on the evaluation of the ﬁnal project: - The ﬁnal project will be assessed based on a presentation during the examination period and the ﬁnal state of the project repository. - The repository must be completed and submitted by Sunday before the start of the examination period (see deadlines above). - Date and time for the presentation will be announced by the administration. - Each group will present the project in 15min, followed by a 10min discussion.
